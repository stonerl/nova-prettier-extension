# Contributing to Prettier⁺ for Nova

Thanks for helping make Prettier⁺ better! This document covers the
development workflow: setup, testing, code style, and the manual formatting
checks. Bugs and regressions go to
[Issues](https://github.com/stonerl/nova-prettier-extension/issues), plugin
and language requests to the
[Discussions](https://github.com/stonerl/nova-prettier-extension/discussions).

## Development Setup

```bash
git clone https://github.com/stonerl/nova-prettier-extension.git
cd nova-prettier-extension
npm install
npm run build
```

`npm run build` generates the workspace-choices table and copies the
translated strings, then bundles the extension scripts via rollup into
`prettier.novaextension/`.

To work on the extension in Nova, point Nova at the built
`prettier.novaextension/` folder (via _Extensions → Global Extensions →
Open Local Extension Folder_, or a symlink into your local extensions
directory).

For diagnostics in the Extension Console, enable the
`prettier.debug.logging` setting (per workspace or globally).

## Project Structure

| Path                            | Role                                                                 |
| ------------------------------- | -------------------------------------------------------------------- |
| `src/Scripts/main.js`           | Extension lifecycle: activation, watchers, commands, dispose         |
| `src/Scripts/format/`           | Format engine: pipeline, request composition, plugin registry, UX    |
| `src/Scripts/env/`              | Environment: Node.js runtime, subprocess contract, module resolution |
| `src/Scripts/settings/`         | Settings: option data, config access, generated workspace choices    |
| `src/Scripts/prettier-service/` | Background service running Prettier over JSON-RPC                    |
| `src/unifiedConfig.json`        | Single source of truth — generates all settings UI surfaces          |
| `scripts/`                      | Build-time generators (choices, translations, version bump)          |
| `prettier.novaextension/`       | The built extension as it ships                                      |

Generated files (`src/Scripts/settings/workspace-choices.js`,
`prettier.novaextension/config*.json`) are regenerated by the build — never
hand-edit them.

## Testing

```bash
npm test
```

`npm test` builds the extension, installs the bundled runtime dependencies
(`npm install --omit=dev --prefix prettier.novaextension`), prunes them, and
runs all test suites in sequence. Individual suites can also be run
directly after `npm run test:setup`:

| Suite                             | Scope                                                                         |
| --------------------------------- | ----------------------------------------------------------------------------- |
| `tests/workspace-choices.test.js` | Project Settings pop-up choices match the generated table and built config    |
| `tests/sql-dialects.test.js`      | SQL syntax normalization and dialect resolution                               |
| `tests/install-lock.test.js`      | Bundled-install lock: acquisition, mutual exclusion, TTL, staleness, takeover |
| `tests/watcher-filter.test.js`    | Self-event filtering for the extension's own bundled-install writes           |
| `tests/resolver-guard.test.js`    | Loadability guard and resolver failure paths                                  |
| `tests/notifications.test.js`     | Notification wrapper and the failure-reason lifecycle                         |
| `tests/format-pipeline.test.js`   | Format pipeline: request composition, error-to-issue mapping, save gates      |
| `tests/options-coverage.test.js`  | Settings ↔ option wiring, checked in both directions                          |
| `tests/restart-cycle.test.js`     | Restart coalescing: redundant triggers join, queued triggers re-run           |
| `tests/runtime-resolver.test.js`  | Node.js/npm runtime detection, managed-tools fallback, PATH repair            |
| `tests/prettier-info.test.js`     | Prettier Info command output                                                  |
| `tests/service-api.test.js`       | Service request contract (ignore path wiring, parser inference override)      |
| `tests/service-smoke.test.js`     | End-to-end: built service + bundled Prettier, bundled-merge and native modes  |
| `tests/external-plugins.test.js`  | Disabled bundled plugin → project's copy is used instead                      |

### Bundled Patches

> npm ≥ 11 skips postinstall scripts, so a plain install leaves the bundled
> plugins unpatched. The test helper applies the bundled patches
> automatically; to apply them manually: `node
prettier.novaextension/node_modules/patch-package/dist/index.js` (run
> from `prettier.novaextension/`). At runtime the extension does this
> itself after every bundled install.

### External-Plugins Fixture

The first run of `external-plugins.test.js` installs the test fixture's
dependencies (`@prettier/plugin-xml`, `prettier-plugin-properties`) into
`tests/fixtures/external-plugin-project/` — network access is required once.

### Verifying the External-Plugin Fallback in Nova

To verify the fallback manually: open
`tests/fixtures/external-plugin-project/` as a project, disable a bundled
plugin (XML or Properties) in the extension settings, and format the
matching fixture file (`test.xml` / `test.properties`). The Extension
Console then logs that the plugin was loaded from your project.

## Code Style & Linting

CI enforces two checks on every PR, both run from the repo root:

```bash
npx eslint . --ext .js
npx prettier . --check
```

Both must pass before merge. `src/Scripts/helpers.js`, `runtime.js` and the
prettier-service modules are covered by the same rules; tests follow the
plain-Node conventions of the existing suites.

## Commit Messages

The repo follows [Conventional Commits](https://www.conventionalcommits.org)
— `type(scope): summary` in the imperative mood, lowercase after the colon:

```text
fix(format): guard getIgnorePath against missing path
refactor(service): inline FormattingService base class
test(options): guard plugin option wiring both directions
```

Types seen in the history: `feat`, `fix`, `refactor`, `perf`, `docs`,
`test`, `chore`, `build`, `ci`. See `git log --oneline` for examples.

## Adding a Bundled Plugin

The wiring is guarded by `tests/options-coverage.test.js` — it fails when
an option list and the settings UI drift apart. A new bundled plugin needs:

1. `prettier.novaextension/package.json` — add the dependency
2. `src/Scripts/format/plugin-registry.js` — add the entry path to
   `pluginPaths` and a `PLUGIN_DESCRIPTORS` entry (`configKey`,
   `pluginPath`, and `optionsConfig` when options are surfaced)
3. `src/unifiedConfig.json` — add the settings section
   (`prettier.plugins.<name>…`) and regenerate the config via `npm run build`
4. `src/Scripts/settings/prettier-options.js` — declare the surfaced
   options in the matching `PRETTIER_*_PLUGIN_OPTIONS` list (the coverage
   test checks both directions)
5. `README.md` — add a row to the bundled-plugin table
6. If the plugin needs patching, add a patch file under
   `prettier.novaextension/patches/` (applied via patch-package) — see the
   Bundled Patches note above

## Formatting Samples

`tests/format-samples/` holds one deliberately formatted file per supported
language. They aren't consumed by any test suite — they exist for the manual
formatter check:

1. Scramble the samples: `npm run prepare:testfiles`
2. Open the folder in Nova and format each file (Editor → Prettier⁺ → Format)
3. Eyeball the result — the scrambled mistakes should disappear

The samples are committed formatted (they're deliberately excluded from
`prettier --check`), so re-run the scramble step whenever you want to test
again. To add a sample for a new language, drop a `*.sample.*` file into
that folder — the scramble script picks formats up by extension.

## Translations

Help translate Prettier⁺ and make it accessible to more developers in your
language — no coding experience required. Contributions happen directly via
[Weblate](https://hosted.weblate.org/projects/prettier-for-nova/); see the
translation section in the [README](README.md) for details.

All contributions are greatly appreciated!
